# 演習 4: 追加機能のIssue作成

| [← 前の手順](./3-monitor-implementation.md) |
|:--|

この演習では、より高度な機能として検索フィルター拡張機能のIssueを作成し、Copilot エージェントとの継続的な協働開発プロセスを学習します。複数の機能を段階的に実装する実践的なワークフローを体験します。

## シナリオ

サポートメニュー機能の実装が成功し、ユーザーからの評価も良好です。このタイミングで、プロダクトマネージャーから既存の検索機能の改善要請がありました。

市場調査により、以下のニーズが明らかになりました：
- **国別検索**: 「日本の旅行先だけを見たい」というユーザーニーズ
- **食文化体験**: 「Food/グルメ」カテゴリへの関心の高まり

これらの機能をCopilot エージェントと協働で実装することが今回のミッションです。

## ? **必須** 1. 高度なIssue作成

### ? Issue作成の準備

前回の経験を活かし、より詳細で具体的なIssueを作成します：

1. 既存コードの理解を考慮した要件定義
2. 技術的制約の明確化
3. ユーザビリティ要件の詳述
4. テストや品質基準の事前定義

### ? 必須 新しいIssueの作成

1. GitHub の Issues ページに移動
2. 「New issue」をクリック
3. 以下の内容で Issue を作成

#### Issue タイトル
```
検索メニューの高度なフィルタリング機能追加
```

#### Issue詳細内容
````markdown
## 概要
既存の検索機能に高度なフィルタリングオプションを追加し、ユーザーがより精密に旅行先を探せるようにする機能の実装。

## 背景
- ユーザーアンケートで「国別検索」への需要が70%以上
- グルメ旅行への関心が前年比150%増加
- 現在の検索は基本的なカテゴリ分けのみで不十分

## 要件

### 1. 国別検索フィルター
- **実装場所**: `components/trips/SearchForm.tsx` の拡張
- **機能**: 旅行先を国別でフィルタリング可能にする
- **対象国**: 日本、韓国、タイ、フランス、イタリア、アメリカ、その他
- **UI**: ドロップダウン形式での選択

### 2. 新カテゴリ「Food」の追加
- **実装場所**: 既存カテゴリ選択機能の拡張
- **内容**: 食べ物・グルメ関連の旅行体験カテゴリ
- **表示**: 既存カテゴリと同等の優先度で表示
- **アイコン**: 食べ物を表現する適切なアイコンを使用

## 技術仕様

### ファイル変更予定
```typescript
// 修正対象ファイル
components/trips/SearchForm.tsx  // メインの検索フォーム
lib/types/index.ts              // 型定義の拡張
lib/data/mockData.ts            // モックデータの追加
```

### 新規追加する型定義
```typescript
// 国フィルター用の型
type Country = 'Japan' | 'Korea' | 'Thailand' | 'France' | 'Italy' | 'USA' | 'Other';

// 拡張カテゴリ型
type TripCategory = 'Adventure' | 'Relaxation' | 'Cultural' | 'Food' | 'Business';
```

### UI/UX要件
- **レスポンシブデザイン**: モバイル・タブレット・デスクトップ対応
- **アクセシビリティ**: スクリーンリーダー対応、キーボードナビゲーション
- **ユーザビリティ**: 直感的なフィルター操作、即座のフィードバック
- **パフォーマンス**: フィルター適用時の遅延なし

## 受け入れ条件

### 基本機能
- [ ] 国別フィルターのドロップダウンが動作する
- [ ] 「Food」カテゴリが選択リストに表示される  
- [ ] フィルター適用時に検索結果が適切に絞り込まれる
- [ ] 複数フィルターの組み合わせが正常に動作する

### データとロジック
- [ ] モックデータに国情報とFoodカテゴリが追加される
- [ ] 型定義が適切に更新される
- [ ] フィルターロジックが効率的に実装される
- [ ] URL パラメータでフィルター状態が保持される

### UI/UX品質  
- [ ] すべてのデバイスサイズでレイアウトが適切
- [ ] フィルター操作が直感的で使いやすい
- [ ] エラー状態のハンドリングが適切
- [ ] ローディング状態の表示が実装される

### 技術品質
- [ ] TypeScript による完全な型安全性
- [ ] Next.js App Router パターンへの準拠
- [ ] 既存コードとの整合性維持
- [ ] パフォーマンスの劣化なし

## 実装上の注意点
1. 既存の `SearchForm.tsx` の構造を保持する
2. 新しいフィルターが既存の検索ロジックと衝突しないよう注意
3. モックデータの整合性を維持する
4. カテゴリアイコンは統一されたデザインシステムに従う

## 成功指標
- フィルター使用率: 全検索の30%以上
- ユーザー満足度: 4.0/5.0以上
- 検索→予約転換率: 現在比120%以上
````
## ? **必須** 2. Copilot エージェントへの割り当て

### ? 必須 高度な割り当て指示

今回はより具体的で詳細な指示でエージェントに依頼します：

```
@copilot この検索フィルター機能を実装してください。

特に以下の点に注意して実装をお願いします：
1. 既存のSearchFormコンポーネントの構造を維持する
2. 型安全性を重視したTypeScript実装
3. Reactのベストプラクティスに従ったstate管理
4. アクセシビリティを考慮したUI実装

実装前に、現在のSearchFormコンポーネントを分析して、
最適な実装アプローチを提案してください。
```

## ? 3. 複数機能の管理

### 並行開発の考慮事項

複数の機能を同時に開発する際の注意点：

- **ブランチ管理**: 機能ごとの独立したブランチ
- **コード競合の回避**: 同一ファイルの変更時の調整
- **統合テスト**: 複数機能の組み合わせ動作確認
- **リリース計画**: 段階的な機能リリース戦略

### エージェント間の調整

複数のIssueでCopilot エージェントを使用する場合：

```
@copilot この検索機能の実装時に、先ほど実装されたサポートメニューとの
ナビゲーション統合も考慮してください。一貫したユーザー体験を提供したいです。
```

## ? **オプション** 4. 高度なコラボレーション

### 実装アプローチの提案

エージェントに実装方針を相談：

```
@copilot 国フィルターの実装で以下の2つのアプローチを検討しています：
1. URLパラメータベースの状態管理
2. ReactのuseStateによるローカル状態管理

それぞれのメリット・デメリットを教えてください。
この機能に最適なアプローチはどちらですか？
```

### パフォーマンス最適化の相談

```
@copilot 大量のトリップデータをフィルタリングする際の
パフォーマンス最適化について、以下の手法の適用を検討してください：
- useMemo によるフィルター結果のメモ化
- useCallback による関数の最適化
- 仮想化による大量データの効率的表示
```

## ? **オプション** 5. 実装品質の向上

### テスト要件の追加

より高品質な実装のため、テスト要件も明記：

```
@copilot 実装と併せて、以下のテストケースも作成してください：
- 国フィルターの動作テスト
- Foodカテゴリの選択テスト
- 複数フィルター組み合わせのテスト
- エッジケース（データなし等）のハンドリングテスト
```

### コードドキュメンテーション

```
@copilot 新機能のコードには、以下のドキュメンテーションを含めてください：
- 各関数のJSDocコメント
- 複雑なロジックのインライン説明
- 型定義の説明コメント
- 使用例のサンプルコード
```
